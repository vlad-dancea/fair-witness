# Development

[mise](https://mise.jdx.dev) pins the Rust toolchain and defines the tasks, and CI runs the same ones:

```sh
mise install            # the pinned Rust toolchain, with clippy and rustfmt
mise run dev -- setup   # run fair-witness from source
mise run format         # format the sources
mise run scenarios      # run the scripted researcher sessions in scenarios/edge-cases/ and scenarios/realistic/
mise run check          # everything CI checks: formatting, clippy, tests, scenarios
```

Clippy warnings fail the check.

The code is split into three crates in `crates/`. `fair-witness-core` is a library that watches the folder, talks to DAMAP and reviews changes, without any terminal code. `fair-witness` is the binary with the commands, the setup questions and the full-screen interface. `fair-witness-scenarios` runs the scenarios in `scenarios/` against the binary, with a fake model or a real one, and is not released. [scenarios/README.md](../scenarios/README.md) describes them.

## The recording in the README

[`demo/record.sh`](demo/record.sh) records `demo/demo.gif` again, such as after a change to the screen. It sets up a demo project against TU Wien's DAMAP as `user` with password `user` and has a model on Aqueduct review two changes, so it needs an Aqueduct API key in `FAIR_WITNESS_API_KEY`. The script lists the tools it needs.

## Releasing

A push to `main` publishes a release once `mise run check` passes on it, if `main` differs from the latest release in `crates/` outside `crates/fair-witness-scenarios/`, `Cargo.toml`, `Cargo.lock`, `dist-workspace.toml` or `.github/workflows/release.yml`. Changes to anything else, such as `.github/workflows/ci.yml`, the README, `docs/`, `mise.toml` or the scenario runner, would build the same binaries and are not released. The runner shares `Cargo.lock` with the binary, so a change to its dependencies that touches `Cargo.lock` still releases. The `publish` job in `.github/workflows/ci.yml` tags the next version (the `version` in `crates/fair-witness/Cargo.toml`, or the next patch if that is already released) and starts `release.yml`, which builds the binaries and installers for Linux, macOS and Windows and attaches them to a GitHub release. To start a new minor or major line, bump `version` in `crates/fair-witness/Cargo.toml`.

The release workflow is generated by [dist](https://github.com/axodotdev/cargo-dist). After changing `dist-workspace.toml`, run `dist generate`.
